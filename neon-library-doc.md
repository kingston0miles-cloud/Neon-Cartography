# Библиотека названий для «Неон-Картограф» — формат `neon-name-library-1`

Документ описывает формат JSON-библиотеки названий: словари, паттерны, токены,
правила валидации и примеры. В конце — готовый промпт для нейросети,
который сгенерирует библиотеку по вашим референсам.

Версия формата: **1**.
Расширение файла: `.json` (рекомендуется `*.neonlib.json`).
Кодировка: **UTF-8**.
MIME: `application/json`.

---

## 0. Как этим пользоваться

1. Откройте «Неон-Картограф» → вкладка **«Названия»**.
2. Нажмите **«Сохранить библиотеку»** — получите текущий JSON со всеми
   встроенными словарями как эталон.
3. Отредактируйте его в любом редакторе **или** передайте в нейросеть
   вместе с промптом из раздела 9.
4. Нажмите **«Загрузить свою библиотеку»** — приложение проверит
   структуру и применит её к текущему городу.
5. Если хотите вернуть встроенный пресет — нажмите «Неон-нуар»,
   «Славянский» или «Техно-утопия» в разделе «Встроенные библиотеки».

## 1. Верхний уровень

Файл — валидный JSON-объект. Никаких комментариев, никаких
дополнительных полей вне перечисленных ниже — лишние игнорируются,
но лучше их не добавлять.

```json
{
  "id": "my-lib",
  "name": "Моя библиотека",
  "lang": "ru",
  "district": { "generic": { ... }, "types": { ... } },
  "street":   { ... },
  "river":    { ... },
  "city":     { ... },
  "park":     { ... },
  "waste":    { ... },
  "special":  { ... }
}
```

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `id` | string | **да** | короткий идентификатор, `[a-z0-9_-]+`, до 32 символов |
| `name` | string | **да** | отображается в интерфейсе пользователя |
| `lang` | string | нет | код языка (`ru`, `en`, `de`, `zh`); по умолчанию `ru` |
| `district` | object | **да** | названия районов |
| `street` | object | **да** | названия улиц, проспектов, переулков |
| `river` | object | нет | названия рек |
| `city` | object | нет | названия городов (для кнопки «Новый город») |
| `park` | object | нет | названия парков, скверов, зон отдыха |
| `waste` | object | нет | названия свалок, полигонов, пустырей |
| `special` | object | нет | названия особых зданий (капитолий, монументы и т.д.) |

**Минимум для валидности:** должны присутствовать секции `district` и
`street`. Остальные — опциональны, но без них часть объектов останется
без имён.

## 2. Спецификация (`spec`) — атомарная единица

Любая из секций (`street`, `river`, `city`, `park`, `waste`, `district.generic`,
`district.types.*`, `special.*`) имеет **одинаковый вид** — это объект `spec`.

```json
{
  "patterns": ["{adj_m} {noun_m}", ["Улица {gen_pl}", 2]],
  "adj_m":    ["Старый", "Новый"],
  "adj_f":    ["Старая", "Новая"],
  "adj_n":    ["Старое", "Новое"],
  "noun_m":   ["Парк", "Сад"],
  "noun_f":   ["Роща", "Аллея"],
  "noun_n":   ["Ядро", "Предместье"],
  "noun_pl":  ["Выселки", "Трущобы"],
  "gen_pl":   ["Кузнецов", "Ткачей"],
  "name_m":   ["Иван", "Синта"],
  "name_f":   ["Волга", "Нева"],
  "prefix":   ["Ново", "Красно"],
  "suffix":   ["град", "бург"]
}
```

### Обязательные поля

- **`patterns`** — массив шаблонов. Каждый элемент — **либо строка**,
  **либо пара `[строка, вес]`**. Вес — положительное число; по умолчанию `1`.
  Чем выше вес — тем чаще паттерн выбирается.

### Необязательные поля-словари

Это массивы строк. Любое из них может отсутствовать, но **каждый токен,
использованный в паттерне, должен быть определён в соответствующем
поле**, иначе этот паттерн выпадает из выборки (см. §6 валидация).

| Словарь | Что содержит | Пример |
|---|---|---|
| `adj_m` | прилагательные, м. род | «Старый», «Кривой» |
| `adj_f` | прилагательные, ж. род | «Старая», «Кривая» |
| `adj_n` | прилагательные, ср. род | «Старое», «Кривое» |
| `noun_m` | существительные, м. род | «Парк», «Завод» |
| `noun_f` | существительные, ж. род | «Роща», «Слобода» |
| `noun_n` | существительные, ср. род | «Ядро», «Предместье» |
| `noun_pl` | существительные во мн. ч. | «Выселки», «Трущобы» |
| `gen_pl` | родительный падеж мн. ч. («чей?») | «Кузнецов», «Ткачей» |
| `name_m` | имена собственные, м. род | «Иван», «Синта» |
| `name_f` | имена собственные, ж. род | «Волга», «Синева» |
| `prefix` | приставки для городов | «Ново», «Красно» |
| `suffix` | окончания для городов | «град», «бург» |

**Смысл каждого словаря фиксирован** — порядок и содержание. Например,
`adj_m` — это всегда прилагательные мужского рода, а не «мужские имена».
Если нужно использовать слова, которые не вписываются в род, кладите
их в `noun_m` и не согласовывайте с прилагательными.

## 3. Токены

В паттернах используются токены вида `{имя}`. При генерации токен
заменяется на случайный элемент из соответствующего словаря.

| Токен | Источник |
|---|---|
| `{adj_m}` | `spec.adj_m` |
| `{adj_f}` | `spec.adj_f` |
| `{adj_n}` | `spec.adj_n` |
| `{noun_m}` | `spec.noun_m` |
| `{noun_f}` | `spec.noun_f` |
| `{noun_n}` | `spec.noun_n` |
| `{noun_pl}` | `spec.noun_pl` |
| `{gen_pl}` | `spec.gen_pl` |
| `{name_m}` | `spec.name_m` |
| `{name_f}` | `spec.name_f` |
| `{prefix}` | `spec.prefix` |
| `{suffix}` | `spec.suffix` |
| `{num}` | **магическое** — целое число 2…99 |

Правила:

- Токен **нельзя** определить в одном словаре и использовать в другом
  (например, `{adj_f}` нельзя положить в `noun_m`).
- `{num}` не требует словаря. Всегда вставляет `rint(rng, 2, 99)`.
- В одном паттерне можно использовать один и тот же токен несколько раз —
  значения будут разными.

## 4. Секция `district` — районы

Объект с двумя полями:

```json
"district": {
  "generic": { ... spec ... },
  "types": {
    "center":      { ... spec ... },
    "commerce":    { ... spec ... },
    "residential": { ... spec ... },
    "industrial":  { ... spec ... },
    "harbor":      { ... spec ... },
    "slums":       { ... spec ... },
    "park":        { ... spec ... },
    "suburb":      { ... spec ... },
    "tech":        { ... spec ... },
    "cemetery":    { ... spec ... }
  }
}
```

- `types` — 10 фиксированных ключей (см. выше). Все **опциональны**.
- `generic` — используется, если для конкретного типа нет своей spec.
- Если **ни для типа, ни generic** нет spec-а, районы этого типа получают
  имя «Район N», где N — число.

Пример типа `residential`:

```json
"residential": {
  "patterns": [
    ["{adj_m} {noun_m}", 3],
    ["{noun_m} {num}", 1],
    "{adj_f} {noun_f}"
  ],
  "adj_m": ["Верхний", "Кузнечный", "Плотницкий"],
  "adj_f": ["Верхняя", "Кузнечная"],
  "noun_m": ["Посад", "Конец", "Двор"],
  "noun_f": ["Слобода", "Застава"]
}
```

**Возможные выходы:** «Верхний Посад», «Кузнечный Конец», «Слобода 42»,
«Кузнечная Слобода».

## 5. Остальные секции

### 5.1. `street` — улицы

Одна spec (не объект с типами). Токены те же, что в §3.

```json
"street": {
  "patterns": [
    ["{adj_f} улица", 4],
    ["Улица {gen_pl}", 3],
    ["Проспект {gen_pl}", 2],
    ["Переулок {gen_pl}", 1],
    ["{adj_m} проспект", 1]
  ],
  "adj_m": ["Новый", "Тихий"],
  "adj_f": ["Новая", "Тихая", "Садовая"],
  "gen_pl": ["Кузнецов", "Плотников", "Ямщиков"]
}
```

**Возможные выходы:** «Тихая улица», «Улица Кузнецов», «Проспект Ямщиков».

### 5.2. `river` — реки

```json
"river": {
  "patterns": ["Река {adj_f}", ["Река {name_f}", 2]],
  "adj_f": ["Тихая", "Быстрая", "Мутная"],
  "name_f": ["Волга", "Ока", "Кама"]
}
```

**Возможные выходы:** «Река Тихая», «Река Волга».

### 5.3. `city` — города

Специфика: чаще всего использует `prefix` и `suffix` (приставки и окончания).

```json
"city": {
  "patterns": ["{prefix}{suffix}", ["{name_f}", 1]],
  "prefix": ["Ново", "Красно", "Бело"],
  "suffix": ["град", "бург", "славль"],
  "name_f": ["Москва", "Рязань"]
}
```

**Возможные выходы:** «Новоград», «Краснобург», «Москва».

> ⚠️ `{prefix}` и `{suffix}` не имеют пробела между собой —
> так они склеиваются в одно слово.

### 5.4. `park` — парки, скверы, зоны отдыха

Одна spec. Не применяется к районам — только к **отдельным blob-объектам**
(те, что рисуются кистью «Парк» или генерируются автоматически).

```json
"park": {
  "patterns": [
    ["Парк {gen_pl}", 3],
    ["Сквер {gen_pl}", 2],
    ["Сад {name_m}", 2],
    ["{adj_f} роща", 1],
    ["Бульвар {gen_pl}", 1]
  ],
  "adj_f": ["Берёзовая", "Липовая", "Тихая"],
  "gen_pl": ["Строителей", "Ветеранов", "Кузнецов"],
  "name_m": ["Теней", "Ветров", "Отдыха"]
}
```

**Возможные выходы:** «Парк Строителей», «Сквер Ветеранов», «Берёзовая
роща», «Бульвар Кузнецов».

### 5.5. `waste` — свалки, полигоны, пустыри

```json
"waste": {
  "patterns": [
    ["Свалка {adj_f}", 2],
    ["Полигон {adj_m}", 2],
    ["Отвал {adj_m}", 1],
    ["Пустырь {num}", 1]
  ],
  "adj_m": ["Северный", "Ржавый", "Забытый"],
  "adj_f": ["Северная", "Заброшенная"]
}
```

**Возможные выходы:** «Свалка Заброшенная», «Полигон Северный»,
«Пустырь 42».

### 5.6. `special` — особые здания

Объект с фиксированным набором подсекций:

```json
"special": {
  "capitol":  { ... spec ... },
  "monument": { ... spec ... },
  "gov":      { ... spec ... },
  "temple":   { ... spec ... },
  "stadium":  { ... spec ... },
  "landmark": { ... spec ... }
}
```

Каждая подсекция — своя spec. Если подсекции нет — для этого типа
зданий имя не сгенерируется, но само здание появится.

| Ключ | Что за здание |
|---|---|
| `capitol` | капитолий / главное административное здание |
| `monument` | монумент, обелиск, стела |
| `gov` | правительственное здание, комитет, управление |
| `temple` | храм, монастырь, святилище |
| `stadium` | стадион, арена, колизей |
| `landmark` | достопримечательность, звезда, око, башня |

Пример:

```json
"special": {
  "capitol": {
    "patterns": [["Капитолий {name_m}", 2], ["Совет {name_m}", 1]],
    "name_m": ["Синты", "Демиурга", "Основателей"]
  },
  "monument": {
    "patterns": [["Монумент {gen_pl}", 2], ["Обелиск {gen_pl}", 1]],
    "gen_pl": ["Строителей", "Победы", "Кузнецов"]
  }
}
```

**Возможные выходы:** «Капитолий Синты», «Монумент Строителей».

## 6. Валидация

При загрузке библиотека проходит проверку. Если что-то не так —
приложение откажется её применять и покажет причину.

### Правила

1. **Верхний уровень** — объект. Поля `id` и `name` — строки. `district`
   и `street` — присутствуют.
2. **Каждая spec** должна содержать непустой массив `patterns`.
3. **Каждый токен** в паттерне (кроме `{num}`) должен быть определён:
   - либо в самом spec-е (`spec.<имя>` — массив строк);
   - либо, если используется спец-словарь (`{prefix}`, `{suffix}`), тоже
     должен быть массивом в spec-е.
4. **`district.types`** — объект; каждая его spec проходит проверку.
5. **`special`** — объект; каждая его подсекция проходит проверку.

### Частые ошибки

| Ошибка | Как исправить |
|---|---|
| `token {adj_f} not defined` | В паттерне есть `{adj_f}`, но массив `adj_f` пуст или отсутствует |
| `patterns must be array` | `patterns` — не массив (например, одна строка вместо `[строка]`) |
| `district is required` | Забыли секцию `district` |
| `id must be string` | `id` — число или отсутствует |
| `unknown token {xxx}` | Опечатка в имени токена |

## 7. Соглашения и рекомендации

### Стиль

- **Читаемость важнее разнообразия.** Имя должно звучать естественно
  по-русски (или на вашем языке).
- **3–7 слов** в словарях — минимум. 10–30 — комфортный рабочий диапазон.
- **Веса** — от 1 до 6. Основной шаблон — 3–4, редкий — 1.
- **Не более 3 паттернов** с весом > 2, иначе выбор «слипнется» на одном.

### Род и согласование

- `adj_m` согласуется с `noun_m`: «Тихий Посад».
- `adj_f` — с `noun_f`: «Тихая Слобода».
- `adj_n` — с `noun_n`: «Тихое Ядро».
- `noun_pl` не согласуется с прилагательными — используйте только с `{num}`
  или отдельно: «Трущобы 42».

### Уникальность

Библиотека не гарантирует уникальность. Приложение уже дедуплицирует
районы по имени и делает до 30 попыток.

### Локализация

- Если пишете библиотеку на английском, укажите `"lang": "en"` и
  убедитесь, что шаблоны грамматически корректны для английского:
  `"{adj_m} {noun_m}"` → «Old Market».
- Приложение не переводит имена между языками. Одна библиотека —
  один язык.

### Производительность

- Общее количество слов в библиотеке — до **5000**.
- Общее количество паттернов — до **500**.
- Крупные библиотеки (>5000 слов) могут замедлить генерацию —
  кэш паттернов ограничен.

## 8. Примеры

### 8.1. Минимальная библиотека

```json

  "id": "minimal",
  "name": "Минимум",
  "street": {

  "district": {

    }
  }
}
```

## 9. Промпт для нейросети

Скопируйте этот блок целиком в чат с любой LLM (Claude, GPT, Gemini
и др.) вместе со списком референсов. Модель вернёт готовый JSON.

````text
Ты — автор процедурных названий для генератора городов «Неон-Картограф».
Твоя задача — сгенерировать JSON-файл библиотеки названий в формате
neon-name-library-1.

# Что я тебе дам

Список референсов: слова, топонимы, имена, цитаты, атмосфера, tone of voice.
Могут быть перечислены через запятую, абзацем или списком.

# Что ты вернёшь

ОДИН валидный JSON-файл в код-блоке ```json ... ```. Без пояснений вне
код-блока. Готов к загрузке в приложение как есть.

# Что такое spec

{
  "patterns": [
    ["{adj_m} {noun_m}", 4],
    ["{noun_m} {num}", 2],
    "{adj_f} {noun_f}"
  ],
  "adj_m": ["...", "..."],
  "adj_f": ["...", "..."],
  "noun_m": ["...", "..."],
  "noun_f": ["...", "..."],
  "gen_pl": ["...", "..."]
}

- patterns — массив; элемент либо строка, либо [строка, вес].
- Вес — целое 1..6, по умолчанию 1.
- Все остальные поля — массивы строк.

# Доступные токены

  {adj_m}    — прилагательное, м. род
  {adj_f}    — прилагательное, ж. род
  {adj_n}    — прилагательное, ср. род
  {noun_m}   — существительное, м. род
  {noun_f}   — существительное, ж. род
  {noun_n}   — существительное, ср. род
  {noun_pl}  — существительное, мн. число
  {gen_pl}   — родительный падеж мн. числа («Кузнецов», «Ткачей»)
  {name_m}   — имя собственное, м. род
  {name_f}   — имя собственное, ж. род
  {prefix}   — приставка (для городов)
  {suffix}   — окончание (для городов)
  {num}      — целое число 2..99, автоматически

# Жёсткие правила

1. Каждый токен в паттерне ОБЯЗАН быть определён в этой же spec-е
   (кроме {num}). Если токена нет в spec — паттерн отбрасывается,
   а валидация может упасть.
2. {prefix} и {suffix} используются только в city; их не надо
   смешивать с прилагательными и существительными.
3. Токены не взаимозаменяемы: {adj_f} — только прилагательные
   женского рода, {noun_m} — только существительные мужского рода.
4. Согласование рода: adj_m + noun_m, adj_f + noun_f, adj_n + noun_n.
5. Стиль: имена должны читаться естественно на русском, 3–7 слов
   в паттерне, разнообразие словарей.
6. Веса — от 1 до 6. Основной шаблон — 3–4, редкий — 1.
7. Минимум 8 слов в каждом словаре, который вы определили.
   Можно меньше, если словарь редкий (например, {noun_n} в 2-3 слова).
8. Не используйте слова вне сеттинга референсов. Если референсы —
   киберпанк, не подмешивайте деревенские топонимы.

# Что делать с секциями

- district: обязательна, все 10 типов, минимум 2 паттерна на тип.
- street: обязательна, минимум 3 паттерна.
- city: если референсы не про города — можно опустить,
  иначе обязательно.
- river, park, waste, special: опциональны, но если включаете —
  дайте минимум 2 паттерна.

# Как работать с референсами

Если референсы на русском и передают определённую атмосферу
(например, «славянское фэнтези, деревянное зодчество, северные
реки»), ты:

1. Собираешь слова по смысловым группам:
   - прилагательные → adj_m/adj_f/adj_n
   - существительные-типы → noun_m/noun_f/noun_n/noun_pl
   - профессии/фамилии → gen_pl
   - имена собственные → name_m/name_f
   - топонимы-основы → prefix/suffix

2. Пишешь 3–6 паттернов на каждую spec, варьируя:
   - конструкцию (прил + сущ, сущ + число, сущ + родительный)
   - порядок слов
   - длину

3. Проверяешь каждый паттерн на грамматику.

# Что уточнить у пользователя ПЕРЕД генерацией

Прежде чем выдать JSON, задай эти четыре вопроса:

1. Список референсов (слова, топонимы, атмосфера).
2. Целевой язык (по умолчанию «ru»).
3. Настроение (мрачное / светлое / эпическое / сатирическое /
   нейтральное).
4. Стиль имён (короткие / длинные, формальные / разговорные,
   пафосные / бытовые).

После получения ответов — верни JSON.
