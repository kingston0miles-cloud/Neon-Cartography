# Руководство по сборке библиотеки имён для «НЕОН-КАРТОГРАФА»

Практическое руководство для пользователя. Как собрать свою библиотеку имён, загрузить её в генератор и получить карты с уникальными названиями. От простого копирования встроенной библиотеки до собственного языка со слоговым слоем.

Версия документа: 1.0. Соответствует «Неон-Картографу» версии 0.9.3 и формату библиотек v2.

## 1. Что такое библиотека имён и зачем она нужна

**Библиотека имён** — это JSON-файл, из которого генератор берёт слова для названий районов, улиц, рек, парков, монументов и городов. Три библиотеки встроены из коробки:

- **Неон-нуар** — киберпанк-стилистика.
- **Славянский** — исторические топонимы.
- **Техно-утопия** — научная фантастика.

Своя библиотека позволяет:

- Сделать мир со своей атмосферой (постапокалипсис, фэнтези, южный портовый город, космическая станция).
- Дать всем объектам имена на вымышленном языке.
- Использовать контекст места: улица в порту звучит не так, как улица в трущобах.
- Уникализировать названия для нескольких городов одного мира.

**Что библиотека не делает:**

- Не влияет на геометрию карты (районы, улицы, дома).
- Не меняет цвета, эффекты, экспорт — всё это отдельно.
- Не сохраняется автоматически в localStorage — только в файл проекта или в отдельный JSON.

## 2. Быстрый старт: своя библиотека за 5 минут

Самый простой путь — скопировать встроенную библиотеку и отредактировать её.

### 2.1. Выгрузить встроенную библиотеку

1. Открой вкладку **«Названия»**.
2. В разделе **«Активная библиотека»** убедись, что выбрана одна из встроенных (например, «Славянский»).
3. Нажми **«Сохранить библиотеку»**. Браузер скачает файл `slavic.json`.

### 2.2. Открыть и отредактировать

Открой файл в любом текстовом редакторе: VS Code, Notepad++, Sublime Text. Требования:

- Кодировка — **UTF-8 без BOM**.
- Не редактируй в Word или Google Docs — они добавляют свои символы и ломают JSON.

### 2.3. Заменить словари

Найди массивы прилагательных и существительных и замени их на свои. Например, было:

```json
"adj_m": ["Верхний", "Нижний", "Заречный"]
Стало:

json
"adj_m": ["Кобальтовый", "Ржавый", "Туманный", "Забытый"]
2.4. Загрузить обратно
Вкладка «Названия» → «Загрузить свою библиотеку».

Выбери отредактированный файл.

Если в библиотеке были ошибки — появится toast с описанием. Исправь и попробуй снова.

Нажми «Перегенерировать все имена», чтобы увидеть результат на текущей карте.

2.5. Что делать, если совсем нет опыта
Собери слова прямо из своих референсов: книг, фильмов, игр.

Начни с одного модуля — например, только street. Остальные оставь как были.

Сохраняй копии перед экспериментами.

3. Формат библиотеки — общий обзор
Библиотека — один JSON-объект. Минимальная структура:

json
{
  "id": "my-world",
  "name": "Мой мир",
  "lang": "ru",
  "format": 2,
  "district": { "...": "..." },
  "street":   { "...": "..." },
  "river":    { "...": "..." },
  "city":     { "...": "..." },
  "park":     { "...": "..." },
  "waste":    { "...": "..." },
  "special":  { "...": "..." }
}
Поля верхнего уровня:

Поле	Обязательно	Что это
id	Да	Короткий идентификатор латиницей без пробелов. Используется в имени файла при сохранении.
name	Да	Человеческое название («Северные королевства»). Показывается в интерфейсе.
lang	Нет	Код языка или вымышленный идентификатор. Отображается в UI.
format	Да	Всегда 2, если используешь слоговый слой. Без него библиотека считается v1.
syllables	Нет	Секция генератора слогов (см. § 7).
district	Нет, но полезно	Имена районов.
street	Да (минимум одно из district/street/river)	Имена улиц.
river	Нет	Имена рек.
city	Нет	Имена городов.
park	Нет	Парки, скверы, аллеи.
waste	Нет	Свалки, пустыри.
special	Нет	Особые здания.
Главное правило: если модуль отсутствует, генератор использует встроенный аналог из библиотеки «Неон-нуар». Если модуль есть — используется он.

4. Модули библиотеки и их назначение
4.1. district — районы
json
"district": {
  "generic": { "...": "..." },
  "types": {
    "center":      { "...": "..." },
    "commerce":    { "...": "..." },
    "residential": { "...": "..." },
    "industrial":  { "...": "..." },
    "harbor":      { "...": "..." },
    "slums":       { "...": "..." },
    "park":        { "...": "..." },
    "suburb":      { "...": "..." },
    "tech":        { "...": "..." },
    "cemetery":    { "...": "..." }
  }
}
generic — резервная спецификация. Используется, если у типа района нет своей или если район смешанного типа.

types — по одной спецификации на каждый из 10 типов.

Если тип отсутствует — берётся generic. Если и его нет — встроенный NEON_LIB.district.generic.

4.2. street — улицы
json
"street": {
  "patterns": [
    ["{adj_f} улица", 4],
    ["Улица {gen_pl}", 3],
    ["Переулок {gen_pl}", 2]
  ],
  "adj_m": ["Кузнечный", "..."],
  "adj_f": ["Кузнечная", "..."],
  "gen_pl": ["Кузнецов", "..."]
}
Паттерны — основа. Каждый паттерн — строка с токенами в фигурных скобках. Второй элемент массива (опционально) — вес.

4.3. river — реки
json
"river": {
  "patterns": ["Река {adj_f}", "Река {name_f}"],
  "adj_f": ["Тихая", "Тёмная"],
  "name_f": ["Волга", "Нева"]
}
4.4. city — города
json
"city": {
  "patterns": [
    ["{prefix}{suffix}", 4],
    ["{root}{suffix}", 3]
  ],
  "prefix": ["Ново", "Старо"],
  "root":   ["волг", "дон", "кам"],
  "suffix": ["град", "славль", "озерск"]
}
Паттерны для городов обычно склеивают части без пробелов.

4.5. park — парки и зелёные зоны
json
"park": {
  "patterns": [
    ["Парк {gen_pl}", 3],
    ["Сквер {gen_pl}", 2],
    ["{adj_f} роща", 1]
  ],
  "adj_m": [],
  "adj_f": [],
  "gen_pl": [],
  "name_m": []
}
4.6. waste — свалки и пустыри
json
"waste": {
  "patterns": [["Свалка {adj_f}", 2], ["Полигон {adj_m}", 2]],
  "adj_m": [],
  "adj_f": []
}
4.7. special — особые здания
json
"special": {
  "capitol":  { "patterns": [], "name_m": [] },
  "monument": { "patterns": [], "gen_pl": [] },
  "gov":      { "patterns": [], "name_m": [] },
  "temple":   { "patterns": [], "name_m": [], "name_f": [] },
  "stadium":  { "patterns": [], "name_m": [] },
  "landmark": { "patterns": [], "adj_f": [] }
}
Каждый из 6 типов опционален. Если чего-то нет — берётся встроенный вариант.

5. Паттерны и токены — как собираются имена
5.1. Что такое паттерн
Паттерн — строка-шаблон, где в фигурных скобках указываются токены. Пример:

text
"{adj_m} {noun_m}"
При генерации каждый {token} заменяется на случайное слово из соответствующего массива. Результат — например, «Стальной Посад» или «Тёмный Квартал».

5.2. Веса
Паттерн может быть строкой или массивом [строка, вес]:

json
"patterns": [
  "{adj_m} {noun_m}",
  ["{noun_m} {num}", 3],
  ["{adj_f} {noun_f}", 0.5]
]
Правило хорошего тона: не давай одному паттерну вес больше 5 при других весах 1 — иначе имена становятся формульными.

5.3. Все доступные токены
Из собственных массивов спецификации:

Токен	Что подставляет
{adj_m}	Прилагательное в мужском роде
{adj_f}	Прилагательное в женском роде
{adj_n}	Прилагательное в среднем роде
{noun_m}	Существительное в мужском роде
{noun_f}	Существительное в женском роде
{noun_n}	Существительное в среднем роде
{noun_pl}	Существительное во множественном числе
{gen_pl}	Существительное в родительном падеже мн. числа
{name_m}	Собственное имя в мужском роде
{name_f}	Собственное имя в женском роде
{prefix}	Приставка (для городов)
{root}	Корень (для городов)
{suffix}	Суффикс (для городов)
Магический токен:

Токен	Что подставляет
{num}	Случайное число от 2 до 99
Свои токены. Можно вводить любые. Если в спецификации есть массив material, паттерн {material} {noun_m} сработает:

json
{
  "patterns": ["{material} {noun_m}"],
  "material": ["Стальной", "Медный", "Ржавый"],
  "noun_m": ["Завод", "Цех"]
}
5.4. Правила построения имён
Порядок слов — как в русском: {adj_m} {noun_m} → «Кузнечный Двор». Если хочешь «Двор Кузнецов», используй {noun_m} {gen_pl}.

Род прилагательного должен совпадать с родом существительного. {adj_m} {noun_f} — грубая ошибка.

Пробелы ставь в паттерне там, где они нужны в имени. {prefix}{suffix} → «Новоград». {prefix} {suffix} → «Ново град».

Проверка грамматики. Если сомневаешься — сгенерируй 20 имён мысленно и посмотри, читаются ли они.

6. Контекстные токены — глубокая настройка под место
Это ключевая фишка версии 2.0. Контекстные токены не нужно объявлять в спецификации — генератор сам подставляет значение в зависимости от того, где создаётся имя.

6.1. Список контекстных токенов
Токен	Что подставляет	Примеры
{terrain_m}	Рельеф места (м.)	«Морской», «Речной», «Горный», «Полевой»
{terrain_f}	Рельеф места (ж.)	«Морская», «Речная», «Горная»
{rank_m}	Удалённость от центра (м.)	«Центральный», «Средний», «Дальний»
{rank_f}	Удалённость от центра (ж.)	«Центральная», «Средняя», «Дальняя»
{age_m}	Возраст застройки (м.)	«Древний», «Старый», «Новый»
{age_f}	Возраст застройки (ж.)	«Древняя», «Старая», «Новая»
{industry_m}	Ближайший промышленный сосед (м.)	«Кузнечный», «Рыбацкий», «Квантовый»
{industry_f}	То же, ж.	«Кузнечная», «Рыбацкая», «Квантовая»
{side_m}	Сторона света (м.)	«Северный», «Южный», «Восточный», «Западный»
{side_f}	Сторона света (ж.)	«Северная», «Южная», «Восточная»
6.2. Как контекст попадает в имя
Генератор определяет точку, где создаётся имя (центр района, середина улицы, координата парка).

Собирает контекст через contextForPoint.

При выборе паттерна проверяет: все ли токены доступны? Если паттерн требует {terrain_f}, а контекст не содержит его — паттерн пропускается, ищется другой.

Если паттерн подходит — подставляет контекстное значение.

6.3. Как использовать в своей библиотеке
Простой пример: улица в порту должна получить «Морскую», а в степи — «Полевую».

json
"street": {
  "patterns": [
    "{adj_f} улица",
    ["{terrain_f} улица", 2],
    ["Улица {gen_pl}", 3]
  ],
  "adj_f": ["Старая", "Новая"],
  "gen_pl": ["Кузнецов", "Рыбаков"]
}
Имена на выходе:

Улица у моря → «Морская улица».

Улица в степи → «Полевая улица».

Улица в любом месте → «Старая улица», «Улица Кузнецов».

Более сложный пример: район в центре с промышленным соседом:

json
"district": {
  "types": {
    "residential": {
      "patterns": [
        "{adj_m} {noun_m}",
        ["{rank_m} {noun_m}", 2],
        ["{industry_m} {noun_m}", 1]
      ],
      "adj_m": ["Жилой", "Тихий"],
      "noun_m": ["Район", "Квартал"]
    }
  }
}
Если жилой район рядом с промзоной и не в центре:

«Средний Район» (rank).

«Кузнечный Квартал» (industry).

6.4. Когда контекст недоступен
Если паттерн использует контекстный токен, а значение не вычислено — паттерн молча пропускается. Это безопасно: если в библиотеке есть только контекстные паттерны, а контекст пуст, генератор уйдёт в fallback и не сломается. Но лучше всегда иметь хотя бы один паттерн без контекстных токенов.

7. Слоговый слой — для экзотических языков
Если твой мир говорит на вымышленном языке, словарей не хватит: 100 слов дадут 100 имён, потом пойдут повторы. Слоговый слой позволяет генерировать новые слова из строительных блоков.

7.1. Как это работает
Генератор берёт секцию syllables.

Случайно собирает 2–3 слога.

Склеивает их.

Проверяет по списку forbid — если найдена запрещённая подстрока, имя отбрасывается и генерация повторяется.

Возвращает имя вида «Вантрия», «Ксирен», «Стелоран».

Слоговый слой вызывается как fallback: если словарный паттерн справился — слоги не используются. Слоги включаются только когда паттерн не дал результата (например, все имена из словаря уже заняты).

7.2. Два способа описания
Способ A: onset + nucleus + coda
json
"syllables": {
  "enabled": true,
  "baseToponyms": true,
  "min_syllables": 2,
  "max_syllables": 3,
  "onset":   ["", "б", "бр", "в", "г", "д", "к", "пр", "ст", "ш"],
  "nucleus": ["а", "е", "и", "о", "у", "ы", "я"],
  "coda":    ["", "", "н", "р", "л", "м", "с", "т", "кс", "рт"],
  "coda_freq": 0.35,
  "forbid": ["жж", "шш", "щщ", "ъ"],
  "capitalize": true
}
onset — начальные согласные и кластеры. Пустая строка "" — слог без начальной согласной.

nucleus — гласные. Обязательно непустой массив.

coda — конечные согласные. Пустая строка — слог без коды.

coda_freq — вероятность того, что слог получит коду (0..1). 0.3–0.5 — славянские языки, 0.5–0.7 — германские, 0.1–0.2 — японские.

forbid — список запрещённых подстрок. Если имя содержит любую из них — оно отбрасывается.

min_syllables/max_syllables — сколько слогов склеивать. 2–3 для топонимов, 1–2 для коротких названий.

capitalize — с большой ли буквы. По умолчанию true.

Способ B: recipes + C + V
json
"syllables": {
  "enabled": true,
  "baseToponyms": true,
  "recipes": ["CV", "CVC", "CVCV"],
  "C": ["б", "в", "г", "д", "к", "л", "м", "н", "р", "с", "т"],
  "V": ["а", "е", "и", "о", "у"]
}
recipes — шаблоны слогов. C = согласная, V = гласная. Можно использовать любые другие символы — они вставляются буквально.

C и V — списки букв.

Выбирай один способ. Если заданы оба — приоритет у способа A.

7.3. baseToponyms — охват
Управляет тем, где используются слоги:

baseToponyms: true — слоги генерируют имена для всего, включая города и реки.

baseToponyms: false — слоги работают только для улиц, парков, свалок, монументов, но не для городов и рек.

Важно: слоговый слой всегда работает для district, street, park, waste, special, независимо от baseToponyms. Флаг управляет только city и river.

7.4. Управление слогами в UI
Во вкладке «Названия» есть:

«Выключить слоги» / «Включить слоги» — глобальное переключение syllables.enabled.

«Слоги только для улиц» / «Слоги для городов и рек» — переключение baseToponyms.

8. Пошаговый рецепт: славянский городок
Соберём простую библиотеку в славянской стилистике, без слогов.

8.1. Подготовка файла
Создай новый файл slavic-village.json со структурой:

json

9.3. Тонкая настройка звучания
Хочешь «мягче» — убери т, к, шт из onset и coda.

Хочешь «жёстче» — добавь больше кластеров (кст, трс, кш).

Хочешь «певучее» — используй только открытые слоги: coda: [""], coda_freq: 0.

10. Проверка библиотеки перед загрузкой
Перед загрузкой в генератор прогони библиотеку по этим пунктам:

10.1. JSON валиден
Открой файл в браузере или редакторе. Если подсветка показывает ошибки — исправь. Типичные проблемы:

Пропущенная запятая между элементами массива.

Лишняя запятая после последнего элемента.

Незакрытая кавычка.

Смешанные кавычки — ' вместо ".

Быстрая проверка: открой консоль браузера (F12), вставь:

js
JSON.parse(await (await fetch('file:///путь/к/файлу.json')).text())
Если не ругается — JSON валиден.

10.2. Все токены определены
Для каждого паттерна в каждом модуле проверь: все {token}, кроме {num} и контекстных, определены в этом же модуле как массивы с непустым содержимым.

10.3. Рода согласованы
Проверь, что в паттернах прилагательное и существительное одного рода:

{adj_m} {noun_m} — ок.

{adj_f} {noun_f} — ок.

{adj_m} {noun_f} — грамматическая ошибка, но валидация пропустит.

10.4. Нет дубликатов
Внутри одного массива проверь, что нет одинаковых слов.

10.5. Слоги (если включены)
min_syllables <= max_syllables.

onset и nucleus — непустые массивы, или есть recipes + C + V.

forbid — массив, если задан.

11. Валидация — что и почему проверяет генератор
При загрузке файла генератор проверяет:

Корень — объект, не null и не массив.

Наличие хотя бы одного из district, street, river.

Если syllables.enabled: true:

есть onset + nucleus, или есть recipes + C + V;

coda — массив, если задан;

каждый рецепт в recipes состоит только из C и V.

Для каждого модуля (street, river, city, park, waste, special.*, district.*):

есть patterns;

каждый паттерн использует только определённые токены.

11.1. Что проверка не делает
Не проверяет грамматику и род.

Не проверяет дубликаты.

Не проверяет осмысленность имён.

Не проверяет размеры массивов.

12. Совместимость версий и обратная совместимость
12.1. Формат v1 (старый)
Библиотека без поля format и без секции syllables — считается v1. Работает в старом режиме: только словарные имена, без слогов.

Можно загрузить v1 в новую версию генератора — будет работать.

12.2. Формат v2 (новый)
Библиотека с format: 2 и (опционально) секцией syllables. Работает с слогами, если они включены.

12.3. Совместимость со старыми проектами
Когда ты загружаешь старый проект (JSON с картой), в нём лежит сохранённая библиотека имён. Если она v1 — она загрузится как v1. Если ты хочешь добавить слоги, открой её в редакторе, добавь секцию syllables и format: 2, сохрани и перезагрузи.

12.4. Автоматическое обёртывание
Если в старом проекте syllables не было, генератор автоматически создаст её с enabled: false.

14. Советы и продвинутые приёмы
14.1. Начни с малого
Не пытайся сразу описать весь мир. Сделай одну библиотеку для одного города.

14.2. Используй контекст
Контекстные токены — мощная штука. Добавь 1–2 паттерна с контекстом в каждый модуль.

14.3. Комбинируй словарь и слоги
Самые интересные библиотеки получаются, когда словарь отвечает за «человеческие» имена («Порт Рыбаков»), а слоги — за «чужие» («Ксарион», «Тэра-Мор»).

14.4. Сохраняй рабочие версии
Перед экспериментом копируй файл.

14.5. Используй «Случайное имя» для тестов
Во вкладке «Названия» есть кнопки «Случайное имя района», «Случайное имя улицы», «Случайное имя реки».

14.6. Названия для городов — отдельная логика
В city обычно нет смысла использовать {adj_m} {noun_m}.

14.7. Слоги для городов — включи baseToponyms
Если словарь city маленький, а ты хочешь разнообразия — установи baseToponyms: true.

14.8. Генерация через нейросеть
Если совсем нет времени/желания собирать вручную — используй документ NAME-LIBRARY-BUILDER.md.

14.9. Совместимость с другими мирами
Не бойся копировать одну библиотеку и немного править под новый мир.

14.10. Что НЕ надо делать
Не используй кавычки ' внутри строк JSON.

Не оставляй лишние запятые после последнего элемента.

Не используй BOM в кодировке.

Не сохраняй в .docx или .pages — только .json.
